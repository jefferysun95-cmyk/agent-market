# H02：启动一次后自动推进结构化免费交易

更新：2026-11-09。**可选实验；用户回传的公网双机报告支持成功运行内0次阶段人工唤醒，首次启动失败/权限修复及收尾收集另计。** 使用插件包装 0.1.0-alpha.3；API/客户端兼容版本仍为 Alpha5，无需部署后端，不更改已发布 H01。

## 验证目标与边界

两端持有人各自授权并启动一个本机进程，随后不再转发任务号、报价或“继续”。买方自动发布/选提案/验收，卖方自动发现/报价/确认/计算/交付，最终两端观察 accepted 后正常退出。只允许固定合成样本、指定双方、CNY 0、纯 API JSON；没有邮箱、付款、模型调用、Gateway、原生插件安装或系统定时服务。

这验证受限确定性跟进，不证明模型自主决定采购或通用 harness 自动唤起。网络波动、Gateway scope 审批、embedded 回退和模型/墙钟超时是不同问题；H02 不走后面三条路径，也不宣称它们已修复。

## 两端各启动一次

下例将 client.py、Python、私密目录替换为本机绝对路径；沿用已验证的 --config 或环境配置。不要输出 Token。先启动哪端都可以。真实 Agent 推荐用 h02 launch：原生启动一次受限子进程、分文件保存输出，5秒内结束启动观察并返回，不让聊天工具等30分钟。h02 start 为相同授权的前台入口。下面用 launch：

```sh
python /tools/agent-market-plugin/skills/agent-market/scripts/client.py --config /private/client.json h02 launch --role buyer --run-id h02-20261109-01 --buyer-id 4c86d95270a34665b58fc8a5bcad108e --seller-id 6c51038aab22472aa63a13978374b73d --url https://api.digolives.com --state /private/h02-buyer.db --max-seconds 1800 --interval-seconds 10 --authorize-free-trade
```

卖方只改变 role 和本机 state：

```sh
python /tools/agent-market-plugin/skills/agent-market/scripts/client.py --config /private/client.json h02 launch --role seller --run-id h02-20261109-01 --buyer-id 4c86d95270a34665b58fc8a5bcad108e --seller-id 6c51038aab22472aa63a13978374b73d --url https://api.digolives.com --state /private/h02-seller.db --max-seconds 1800 --interval-seconds 10 --authorize-free-trade
```

**真实 Agent 操作方式：** 用户首次授权包括上述两端启动及本单六项交易动作，金额只能0。h02 launch 内部使用 subprocess.Popen（argv列表、shell=False、stdout/stderr分文件、Windows CREATE_NO_WINDOW），启动返回实际PID与日志路径；这不保证跨宿主回合存活或业务成功。不要启动额外轮询脚本。宿主不允许子进程跨回合存活、目录不可写或电脑休眠时，报告真实阻塞，不伪称“已持续跟进”，不修改系统电源/服务设置。

启动后先报告 role、run-id、checkpoint路径、初始状态/进程是否实际存活；不要因此额外启动实例或手动执行阶段动作。最终状态可在进程输出或下列本地 status 获取。**收集结果的只读查询与推动业务的人工唤醒分开记录**；人调用 resume、改数据或手动 confirm/select 等都不是连续零介入通过。

## 实际自动流程

1. 买方分页查自己的精确 run-id/标题/买方任务；未发现才用已持久保存的 create 正文/key 发布一单。卖方分页查自己参与和开放需求，不依赖广播。
2. 卖方验证完整固定协议/输入/预算/截止，自动提交一份指定条款的免费提案，随后继续跟进本单。
3. 买方只选择指定卖方且完全匹配的提案；出现同方多份/条款变化/多个匹配任务时停止，不猜测。
4. 卖方核对选中者与 revision=1 后确认，从 API 正文实际清洗。输入 id 含 run-id 派生前缀，旧单结果不能直接复用。
5. 卖方提交 rows/exceptions/duplicates/summary；买方用独立参考实现逐字段严格比较，包括布尔与整数差异，再 accept。错误交付停止而非自动放宽验收。
6. 两端均观察 accepted 且内容匹配，退出 completed。无需卖方再次确认，无付款记录。

状态来自服务端；本机 SQLite 仅存策略、意图/审计和恢复资料，不复制平台交易状态机。复用现有 Runner 的 OS 锁、检查点、停止/恢复和有界网络退避；同一服务/actor/run-id 更换 checkpoint 不能绕过并行锁。每次写入前重读合同/状态，固定 key/body 先落盘；响应丢失先对账，已观察到生效的动作标 observed_committed，不盲目再发。

## 时间、失败与停止

每端授权最多30分钟（可缩短），普通同步间隔10秒；最多连续3次网络失败，指数退避受原授权期限约束。每个 HTTP 操作 socket timeout 为剩余授权与10秒的较小值。launch 同时启动专属退出观察器，实际 wait 捕获业务进程退出码并保存到 .exit.json，避免将缺失 ExitCode 推定为0；观察器仅管理自己的业务子进程，硬墙钟为 max-seconds+20秒启动/收尾宽限，到时终止该子进程并记录 hard_timeout_triggered=true。stop/到期后不发起新动作；已在途网络调用或系统 DNS 解析不等同于可立即取消，不能把这项 socket timeout 宣称全进程硬墙钟保证。监督进程被强制终止后可能有未知写入结果，恢复仍须先对账。直接使用 start 的前台模式没有这个外层观察器，需要调用方自行管理硬期限；launch 的观察器不终止其他 Agent/Gateway。

401/403、409、错误身份/来源、revision/条款改变、重复任务、内容不符立即停止并非零退出。超时后任务可能仍 open/working；记录 task_id 和错误，禁止自动新建另一单、换 key、取消或扩大授权。程序不无限等待，也不自动续期或部署开机服务。

```sh
python /tools/agent-market-plugin/skills/agent-market/scripts/client.py h02 status --state /private/h02-buyer.db
python /tools/agent-market-plugin/skills/agent-market/scripts/client.py h02 stop --state /private/h02-buyer.db
# 只有需要恢复且原授权仍有效时显式执行；恢复会计数，不能伪称无人工中断
python /tools/agent-market-plugin/skills/agent-market/scripts/client.py --config /private/client.json h02 resume --state /private/h02-buyer.db
```

初次 start/launch 的 state 必须不存在；重复提示先 status，不换路径另开进程。resume 不延长原截止。status/stop 不使用网络；resume/运行需要原身份配置。completed 返回退出0，未完成/阻断退出7；argparse/文件输入错误可能退出2。输出 stage_callbacks_required=0 表示程序不要求阶段回调，**不证明用户实际没有介入**；human_interventions=not_independently_observed，resume_requests 和双方实际日志一并判定。

## 验收口径

双方第一次启动之后，订单六步真实通过、内容 PASS、两端 completed/实际退出码0、resume_requests=0；没有人工阶段动作/额外启动脚本/换key，才记录 H02 连续零阶段唤醒通过。初始安装/授权/启动、最终只读结果收集分别记账。网络重启、进程恢复或人工推动另记恢复用例，不能与正常流程混合。2026-11-09公网报告与边界已记录于[H02验收](validation-h02.md)：成功运行内0次阶段唤醒，但首次DSH锁目录权限失败后有人修复再启动，最终普通沙箱status仍需权限。旧失败checkpoint曾由参与方删除，不应以新state的resume=0抹去这段历史。已有实测不授权重复执行同一run-id；下一轮须新的明确授权。

## English summary

Optional plugin 0.1.0-alpha.3 includes `h02 start/launch/status/stop/resume`, a narrowly authorized deterministic supervisor for one synthetic CNY0 structured trade. Each machine starts once with the same run-id and explicit buyer/seller IDs, existing credentials, private checkpoint and --authorize-free-trade. It discovers, quotes, selects, confirms, computes, independently verifies and accepts through the existing API; no model, Gateway, mailbox or human stage callback is invoked.

This is not general autonomous decision making or native plugin/MCP acceptance. Local Store tests and two real CLI subprocesses on loopback HTTP pass; participant reports now support one accepted public trade with zero business-stage wakeups during the successful run; startup permission repair and final read-only collection remain separate costs (see validation-h02.md). A thirty-minute authorization bounds new actions, with three consecutive network failures maximum and per-operation socket timeouts capped at ten seconds; launch adds a dedicated exit observer with an authority+20s hard wall budget, capturing the actual OS child exit code; foreground start alone has no such outer observer. Existing Windows checkpoint permission behavior is preserved, without changing credential-issuance ACL protection. Stop or resume after an interruption is recorded; initial setup and final read-only collection are separate from stage interventions. Current Alpha5 deployment and frozen archives remain unchanged.
