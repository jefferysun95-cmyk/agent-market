# Alpha5：真实 OpenClaw 适配与持续跟进设计

状态：设计待实现，2026-11-08。承接 `8271e2b` 的通用运行器、宿主、发现和邮件核心；不代表已经接通真实 OpenClaw，不改变线上 alpha.4。联调安排见 [V05](validation-v05-plan.md)。

## 目标与分工

用户首次配置、授权并分别启动两端后，正常任务无需转发任务号、提醒确认或传输附件。运行器负责等待与确定性动作；OpenClaw 只在确需判断或业务加工时运行一轮。保持平台单服务和 SQLite，不增加消息队列、微服务或平台注册系统。

| 部件 | 职责 | 不能代替的事情 |
|---|---|---|
| 平台 API / progress / inbox | 当前订单、权限、revision、通知、文件证据 | 不知道本机进程、模型余额和 Gmail 密钥 |
| 本地 supervisor | 持久发现、工作登记、调度、停止、恢复、动作提交 | 不按模型口头描述判定成交或验收 |
| OpenClaw adapter | 唤起真实模型回合，把受限工作映射为结构化决策 | 不伪造模型结果，不静默切换运行模式 |
| 本地业务处理器/验证器 | 清洗结果检查、CSV 渲染、买方私有验收 | 不把私有标准答案交给供给方模型 |
| 标准邮件桥 | 真实收发、实际头与附件核验、发送对账 | 不以 SENT 证明收件，不手工补观察值 |

## 1. OpenClaw 适配

### 显式运行模式

本机已只读确认 OpenClaw 2026.4.11 的 agent help 支持 `--local`、`--agent`、`--session-id`、`--json` 和 `--timeout`；尚未证明 Quincey 电脑版本、模型授权及工具配置相同。

首版选择**用户明确配置的 local/embedded 模式**，以专用会话调用真实 OpenClaw；不改变用户正在使用的 Gateway/聊天会话。原因是之前 Gateway 分发曾出现 pairing_required，不能把自动 fallback 当作成功适配。local 仍须具备邮箱持有者/机器用户已授权的模型配置、工作目录和工具权限。

Gateway 模式只在该设备配对、实际响应协议及强制执行路径验证完成后另行启用；禁止 local/Gateway 失败后互相静默降级。若当前宿主不能使用所选模式，应在发布任务前报阻塞。

适配器调用绝对路径的受信运行时和 OpenClaw 入口，shell=False，不执行 cmd/bat 或任务文字拼成的命令；不使用 `--deliver`，不向微信或其他聊天渠道发回复。

### 预检和身份绑定

每台机器冻结一个私密 host profile：平台 actor ID、本机 OpenClaw agent ID、执行模式、绝对入口/运行时路径、允许的工作目录、超时、模型配置引用。平台显示名 AngelX/Quincey 不等于 OpenClaw 内部 agent ID，不凭名字猜测。

预检按顺序验证：安装与 CLI 参数 → 平台自己的 `/me` → 自己 Gmail profile → 真实 OpenClaw 只读一轮。只读回合仅处理合成 nonce/结构化返回，不发信、不创建任务、不改业务数据。保存实际子进程、版本、退出码、响应绑定和模型元数据；不能用固定脚本输出冒充模型执行。

OpenClaw `--json` 的实际返回字段须在两台机器实测后建立版本化映射；字段缺失或格式未知应阻塞，不猜测嵌套路径。完整原始输出只按调试授权存本机私密位置，公开报告仅保留必要元数据。

### 一个工作、一份结果

复用运行器 work_id；按 actor/task/work_id 派生稳定专用 session_id，同一工作恢复不另建聊天会话。attempt 单独递增。一次只允许一个该 actor 的模型工作，避免两个回合同时改同一批文件。

在宿主允许的私密工作目录创建 `work/<work_id>/request.json` 和候选结果；请求已存在但内容不同就停止。提示只指向受信请求文件，不包含 Token、OAuth 内容或私有答案。平台/邮箱凭证由运行器和邮件桥持有；不把密钥作为 OpenClaw 命令参数或模型消息。

模型返回**决策/候选结果**，不把自然语言“完成了”直接映射为业务完成。拟新增的协议 v2 需包含 work_id、observed_revision、输入 manifest、决策类型、结果文件路径及 SHA256；仅允许受信工作目录内的常规文件。拒绝路径越界、符号链接绕过、未知字段、NaN、过大结果和不匹配的工作/版本。协议版本由本地 profile 明确选择；保留当前 v1 通用宿主和邮件 worker，不把新字段直接塞进现有严格 v1 回报。

运行器独立核对决策、约定、当前状态后提交真实 API；提交前持久保存精确 body/key。报价/选择由限额、供给方名单及规则哈希检查；清洗 JSON 经校验后由受信渲染器输出 CSV；accept 仅在买方私有验证器通过后执行。模型工作包只含加工/判断需要的快照，不包含平台或邮箱密钥/授权路径；启动时不把 MARKET_TOKEN、管理员邀请码等环境值传给模型进程。已有宿主自身会注入的工具/环境配置也必须经过预检，不能仅依靠提示词声称隔离。

这需要对当前 generic host 契约做显式演进：`host completed` 只代表宿主回合完成；`business confirmed` 必须由新读的平台状态证明。不能把旧 host ack 直接当成已发送邮件或已验收。受信宿主仍以当前用户权限运行，这不是对恶意本机程序的安全容器；实际可用工具限制必须在预检中确认。

### 失败与停止

模型 402 只从受信宿主实际错误/明确 provider 元数据分类；不匹配“余额”关键词、不依据订单文本推断。无法辨认来源就记 host_failed，并保留来源不明这一事实。

超时或 stop 终止本次专用进程树，确认退出后才报告停止；不结束用户整个 OpenClaw Gateway、其他会话或所有 Node/Python。候选文件和未确认 API 意图保留。若模型回合已完成且候选文件绑定/哈希有效，恢复直接验证该文件，不重复消耗模型；无法确认时以同 work_id 重试，不替换业务 key。

## 2. 持续跟进：从发现到单笔工作

### 复用本地 SQLite 工作登记

在现有 supervisor/discovery checkpoint 中增加 jobs 和待办登记，引用现有单笔 runner checkpoint，不增加交易状态机。每项关联 origin/actor/task_id/run_id、revision、最新 input/output manifest、通知/事件游标、待办、原始 body/key、宿主 work/session/attempt、文件引用与哈希、最近同步、下次重试和到期时间。只保存凭证路径。

供给方首次分页查开放需求，随后交替检查开放需求、inbox 和自己的未完成订单；不能只看 scope=mine，也不能只查 inbox。买方从发布意图恢复自己的订单。发现与注册子工作同事务落盘，通知 ack 只说明“已持久接收”，不是业务完成；业务结果另行确认。

子工作 ID 由 origin/actor/task_id 确定；同一身份重复启动不能创建第二份工作。若进程在文件创建与登记之间退出，恢复核对原 checkpoint 身份及策略哈希，禁止静默覆盖。一次试点先限制每个供给方最多 1 个活跃订单，不自动扩大并发。

当前 discover 的“宿主处理完一项需求”不会自动保证后续确认/交付，这是必须补的缺口：报价成功后由 supervisor 持久接管该 task；宿主不得后台派生另一个脱管轮询进程。supervisor 在各单笔工作间推进，模型/邮件只是有界的受管子任务。

### 正常流程责任表

| 实际条件 | 自动责任方与动作 | 等待约束 |
|---|---|---|
| 有匹配开放需求 | Quincey 读全文、规则/预算检查、经 OpenClaw 决定是否报价；一次报价后登记单笔工作 | 不要求用户给任务号 |
| 有合规提案 | AngelX 比较当前提案并按预授权选择；核对最新 revision | 不继续等不存在的“接单”事件 |
| awaiting_confirmation | 双方独立读取自己的 Gmail profile 并登记邮箱；Quincey 在双方登记齐全后 confirm | 不等输入邮件才确认，不等对方先填自己的邮箱 |
| working，无输入清单 | AngelX 登记文件清单、标准桥真实发送 | 发送地址从本单双方登记读取并核对授权，不需每单人工填写 |
| 输入已发未收 | Quincey receive、核验并登记观察值 | 包含 Spam/Trash；pending 有期限，不手工补回执 |
| 输入已核验 | Quincey 的真实 OpenClaw 清洗；程序核验候选并生成三个 CSV | 不读取买方标准答案或复用旧单文件 |
| 输出就绪 | Quincey 登记清单、发送并提交绑定清单的 JSON | deliver 不等待买方 received，避免互等 |
| delivered/输出已发 | AngelX receive、独立验证内容及双向证据；通过后 accept 一次 | 不把服务端允许 accept 当作内容验收通过 |
| accepted | 双方终止该单工作，通知/发现者不再轮询它 | 免费任务不新增供给方确认或付款 |

### 调度与恢复默认值（实现时冻结）

- 试点总授权 30 分钟；每次恢复沿用原绝对到期及累计预算，不续时。
- 普通 API 观察约每 20 秒，仅程序等待，不调用模型；可加受限抖动。任一单笔写入前重读当前版本。
- 报价/选择等待上限 5 分钟，确认 5 分钟，单向邮件 pending 3 分钟，业务处理单次模型上限 120 秒、最多 2 次尝试；均受总授权上限约束。对端晚启动导致到期应明确报超时，不自动重建任务。
- 连续网络失败最多 3 次，按已有运行器的有界退避处理；401/403/409、身份/版本/文件不符、402、邮箱授权失效立即结束相应执行并报告具体责任。
- 有界 host 返回 pending 时，不能只退出后等聊天唤醒：由 supervisor 保留待办并在下次调度查询同 work_id，或接收已验证的 host ack；未配置该机制则预检失败。
- stop 同时设置 supervisor 及其已登记子工作的停止标志；处理中子任务按专属进程树清理。父进程意外死亡后，恢复检查 OS 锁、宿主结果、API 状态及 outbox，不凭旧 PID/界面判断在线。
- 消息晚到、重复提示、进程重启不得倒退事件位置、替换幂等键、重发不确定邮件或跳过内容验收。working 后不自动换供给方。

## 3. 实施顺序与出口

| 顺序 | 必须交付 | 检查出口 |
|---|---|---|
| A | OpenClaw profile、只读预检、显式 local 适配、专用会话和结构化结果映射 | 两台电脑分别有真实模型回合证明；无业务写入 |
| B | 决策/候选校验及程序执行门槛 | 非法结果、超范围选择、伪回执和路径越界被拒绝 |
| C | jobs 登记、发现后接管、inbox/开放任务补查、pending 再调度、父子 stop/resume | 两种启动顺序、响应丢失、重复启动和重启的本地回归 |
| D | V05 限定业务处理器、私有验收、双方启动包和只读 readiness 报告 | 固定 commit/包哈希；无原始密钥和答案进入供方包 |
| E | V05 两个正常用例，再做恢复/可选 Richard 用例 | 按 V05 逐项判定，不用人工推动的单子冒充正常自动化 |

这些是后续代码交付，不是已有能力。每项同步 CLI/Skill 指引、契约、测试、CHANGELOG 和草稿 PR；最终范围冻结后才发新版本及备份，不覆盖 alpha.4 资产。
