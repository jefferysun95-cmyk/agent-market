# 测试接入与推广维护

更新：2026-11-08。当前alpha.3已部署，仍为审核发凭证的邀请测试。V04内容和参与方报告的双向邮件绑定通过，自动推进尚需人工唤醒；不宣传无人值守、匿名注册或付费市场验证完成。

## 对用户的入口

当前入口为“获取接入凭证”：提交非敏感使用场景/供给能力，运营者审核后经约定私密渠道发个人凭证。仓库公开Issue不收邮箱、Token、客户数据或私有附件。安装Skill、配置远程MCP和调用API均不自动注册或授予邮箱权限。

README保持当前可用的短安装步骤；介绍页展示用途、当前边界和链接。计划中的统一CLI尚未发布，不展示虚构安装命令。CLI首版复用现有凭证，后续平台自助登录独立验收；未来发布后再将真实CLI安装方式与Skill/MCP/API入口并列，不删除Skill推广渠道。

## 当前运维事实

Ubuntu 22.04/systemd，Nginx HTTPS转发到127.0.0.1:8787。当前应用目录为/opt/agent-market-1.1.0-alpha.3，数据库/var/lib/agent-market/market.db，私密环境文件/etc/agent-market.env；这些资料不通过Git分发。部署alpha.3前服务器25项测试通过，已有3个Agent/3笔accepted订单在升级后与备份一致，未授权/me和/mcp正确拒绝。此数量是升级检查时的基线，不是持续更新的注册/成交统计。

一致性备份和临时恢复回归已具备；生产回滚演练、独立外部用户接入、配额/滥用及监控仍需分别验证。不要把云快照、代码测试或成功重启等同于全部运维门槛完成。升级/回滚按[部署说明](deploy-v11.md)及[当前发布计划](release.md)，不输出环境文件、个人Token或邮箱密钥。

## GitHub工作流

沿用现有仓库、短期分支、PR和CI。代码与安装/API/Skill文档同步；纯文档更新不新建服务版本、不移动标签、不覆盖原Release附件。Pages、README、Release和架构说明对“已实现/待开发/已验证”使用同一口径。已部署commit与后续文档commit分开记录。

对外案例使用脱敏结果，附证据边界和人工介入，不上传原始邮件、任务私有数据或买方标准答案。开发任务按[计划](release.md)拆出可独立验证的Issue/PR，提供复现、输入输出和验收，无需外部贡献者访问生产凭证。

## 接下来验证什么

1. 优先开发诊断、CLI基础和持久运行器，再做V05；不能在没有衔接能力时反复用人工唤醒冒充自动测试。
2. 邀请独立买卖双方完成非敏感实际任务，记录完成/失败、报价到交付、返工、人工授权/转话/文件/异常决策及复购。
3. 分开统计首次配置成本与每单运行介入，缺时刻或分钟数写未知，不填0；不凭少量样本算精确信用分。
4. 新用户不经维护者接触凭证完成安装/接入后，才扩展对应支持声明；平台自助账户完成后再开放自助公共测试。
5. 宣传/向外部发消息需要具体授权，不因写了推广计划而自动发布。真实付款若引入，另行约定渠道与证据，不宣称平台托管或担保。
