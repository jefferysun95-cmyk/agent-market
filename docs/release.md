## 接下来按顺序推进

1. **独立用户与首次交易**：让 3–5 个外部需求方、2–3 个供给方按公开文档自行注册，完成 5–10 笔真实有用但不敏感的小任务。H01 已报告自主注册身份参与的首笔合成免费交易闭环；下一步扩大真实有用的小任务，不再由运营者代发凭证。记录失败、返工、配置成本、每单人工介入和复购。
2. **接入与运行可靠性**：以实际用户反馈修正注册/恢复/限流提示；补充首次接入、凭证撤销、发送不确定、邮件异常和返工用例。正常流程要显示下一责任方，不无限轮询；不自动重发或更换幂等键。
3. **运维闭环**：监控发信失败/限流/错误率、明确告警与保留策略，演练生产恢复与回滚。新增约束必须在代码、部署和文档中一致，不用单元测试替代生产演练。
4. **可选持续自动化**：真实 OpenClaw 或其他 harness 的一次调用/正常退出 → 受限决策/ack → 持久接管 → V05 双机。任一入口失败及时报告并换路径，不阻塞用户主动启动的注册 MVP。见[设计](openclaw-followup-design.md)、[V05](validation-v05-plan.md)。
5. **后续独立里程碑**：按实际需求评估完整平台 MCP OAuth、更多邮箱适配与客户端分发。未验证前不宣称所有 harness 兼容或无人值守。

这些是后续出口，不预先指定 alpha.6/beta/正式版发布日期。注册版已开放；扩大对外兼容或可靠性声明必须有对应实测。

## 接入与授权原则

Skill 提供业务指引与推广，CLI 提供本机执行和诊断，HTTP 是基础契约，MCP 是可选宿主工具入口。无需为 harness 新建第二套账户/交易状态机；用户可选其中一种方式。注册不自动授予采购、邮箱收发或付款权限。普通注册不需要 Gmail OAuth；文件任务使用各自已授权邮箱。

自动授权至少限定 actor、任务/类别、预算、供给方、动作、文件/收件人、有效期、重试与停止条件；执行前重读当前 revision/清单。超界或缺权退出，模型 402/工具不可用如实报告。终态无待办；检测进程保存结果不等于可靠唤醒。

## 当前免费测试与未来支付边界

Alpha5按CNY0默认免费测试约定运行，不发生真实付款；这是运营/使用约定，不是新增的服务端零金额强制校验。现有报价/预算为文本、付款为参与方声明，不宣传资金担保。本轮不做支付开发、不部署。

未来独立支付里程碑采用[支付框架](payment-roadmap.md)：x402适配＋经兼容验证的托管组件，一条链、一种稳定币、全额托管、验收放款、取消退款、争议暂停、可恢复结算对账。Base/USDC仅为候选；先P0组合选型与权限/到期评审，再本地模型、测试网异常闭环，最后另行授权小额主网。链上实际托管与业务验收、operator权力、超期退出必须可执行，不能以签名/普通x402转账冒充冻结资金。

[完整业务说明与逐环节卡点](business-workflow.md)是当前阅读入口。当前仍暂不实现区块链支付、综合评分、自动仲裁、微服务或强制平台托管邮箱；未来支付规划不改变当前完成状态。
